项目定位：面向基层政务的AI+RPA智能自动化系统（不是通用RPA）
核心卖点：AI业务判断 + PII隐私脱敏 + 人工审核兜底（三件套缺一不可）
目标用户：街道办/社区基层政务人员
参赛赛道：高教主赛道 → 本科生创意组 → "人工智能+"类
技术栈不变：Vue 3 + Tauri 2 + FastAPI + Playwright + SQLite
功能边界：上述"保留并强化"清单内的功能，清单外的不做
开发节奏：先补P0安全模块 → 再加P1场景功能 → 最后打磨体验

🧠 AI智能层（核心壁垒）

自然语言建任务：用户说人话，AI解析成可执行规则（nl_parser.py）

四层智能自愈：页面改版后自动重新定位元素（self_healing.py）

OCR文字识别：读取扫描件/图片中的文字（ocr动作）

AI结构化抽取：从非结构化文档中提取关键字段（llm_extract动作）

异常智能预警：AI判断数据是否合规，异常自动标记


🤖 自动化执行层（基本功）

操作录制：录一遍自动生成规则（recorder.py）

精简后的动作库：保留政务高频动作（点击、输入、下拉、上传、滚动、提取、等待、跳转、判断、foreach、foreach_if、export），约15种

定时调度：cron/间隔/指定日期触发，重启自动恢复（scheduler.py）

执行报告：每步日志、截图、自愈过程记录（report.py）


🛡️ 安全合规层（评审必看的"护城河"）

PII脱敏网关（⚠️ 需新开发）：数据进入AI前自动掩码敏感信息，AI返回后反向还原

人工审核队列（⚠️ 需新开发）：异常数据进入待审核列表，人工可"通过/驳回/修改"

操作审计日志（⚠️ 需新开发）：记录操作人、时间、对象、类型，支持查询导出


多格式文档解析：PDF/扫描件 → OCR → 结构化数据

报表功能
1. 数据源接入与识别（Input）

这是报表的源头，基础功能必须能搞定两件事：

跨系统自动抓取：利用 Playwright 模拟登录政务专网系统，自动点击、翻页，把网页表格里的数据抓取下来。（基础动作： click ,  extract_table ）

文件解析与识别：支持读取本地的 Excel、CSV 文件，或者通过 OCR 识别扫描件/图片中的表格数据，并转化为统一格式。（基础动作： read_excel ,  ocr_to_json ）


2. 数据处理与总结（Process）

拿到原始数据后，系统得具备基础的加工能力：

基础数据清洗：去重、空值处理、格式统一（比如把各种奇葩格式的日期统一成  YYYY-MM-DD ）。

AI 语义总结：把抓取的原始表格数据丢给大模型（LLM），让它生成一段“数据摘要”或“异常预警”。比如：“本月新增低保户50人，环比上升10%，主要集中在XX街道。”（基础动作： llm_summarize ）


3. 报表生成与输出（Output）

处理完的数据，得能变成基层人员需要的最终形态：

模板套用与渲染：系统内置标准的政务报表模板（Word/Excel），把处理好的数据自动填入对应的单元格中。

多格式导出：支持一键导出为  .xlsx （用于后续计算）、 .pdf （用于打印上报）、 .docx （用于公文附件）。


4. 跨平台流转与填报（Cross-platform）

这是 RPA 结合报表的最核心价值，基础功能必须包含：

跨系统自动填报：把生成的报表或提取的数据，自动打开另一个政务系统，模拟人工点击“上传附件”或“逐行录入”。

执行日志与截图：跨平台操作极易出错，基础功能必须包含：每执行一步都记录日志，遇到报错自动截图保存，方便人工排查。

为了避免大创项目烂尾，请严格按照以下依赖顺序开发：

Phase 1: 跑通最小闭环（MVP）

目标：能手动触发一个任务，自动打开浏览器，完成一次输入并截图。

交付物：Playwright 执行器 + Vue 简单表单 + SQLite 基础表。

Phase 2: 补齐合规三件套（省金关键）

目标：数据流转经过脱敏，异常能暂停，操作有日志。

交付物：PII 网关 + 审核队列 + 审计日志模块。

Phase 3: 智能化与易用性

目标：能用自然语言建任务，能自愈，有模板。

交付物：NL Parser + 自愈引擎 + 模板中心。
